# Turnpike Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Cloudflare Worker that routes OpenAI-compatible and Anthropic-compatible requests to API-key and OAuth-backed upstreams, with fallback, spend and rate limits, per-friend router keys, and a web dashboard.

**Architecture:** A Hono Worker fronts one SQLite-backed Durable Object (`Hub`) that holds all state: accounts, tokens, router keys, combos, limits, and the usage ledger. Limits, cooldowns and token refresh are atomic inside the Hub. The dashboard is static files served by Workers assets, with no build step. `wrangler dev` and `wrangler deploy` run the same code.

**Tech Stack:** TypeScript, Hono, Cloudflare Workers + Durable Objects (SQLite), Wrangler, Vitest with `@cloudflare/vitest-pool-workers`.

**Spec:** the Design section below. The approach (one Durable Object holds all state) was approved in conversation on 2026-11-22. No separate design doc exists.

## Design

- **Client endpoints:** `POST /v1/chat/completions` (OpenAI), `POST /v1/messages` (Anthropic), `GET /v1/models`.
- **Upstreams:**
  - API key: OpenRouter, OpenCode Zen, OpenCode Go, custom OpenAI-style, custom Anthropic-style.
  - OAuth: GitHub Copilot (Claude dropped and Codex deferred, see Task 9).
- **Models and combos:** a request model is `provider/model` or the name of a combo. A combo is an ordered list of `{accountId, model}` targets. The router tries targets in order and falls through on eligible errors.
- **Router keys:** each has a name, optional daily and monthly USD caps, and an allow-list of account ids (`null` means all). Keys are stored as SHA-256 hashes. The secret is shown once.
- **Upstream limits:** per account, optional RPM, TPM and monthly USD caps. A 429 or `Retry-After` from upstream puts the account in cooldown.
- **Subscription accounts:** they count requests and tokens only, with no USD.
- **Admin auth:** `ADMIN_TOKEN` secret, sent as a Bearer token. If it is unset, `/admin/*` returns 503.
- **OAuth:** GitHub Copilot uses device flow. Claude and Codex logins were dropped or deferred (see Task 9).

## Global Constraints

- TypeScript strict mode. The only runtime dependency is `hono`.
- No dashboard build step: static HTML and ES modules in `public/`.
- `wrangler deploy` must work with no resource IDs to paste in. Use only the Durable Object binding `HUB`, and use the `new_sqlite_classes` migration.
- Secrets (provider tokens, API keys) are never returned by admin list endpoints. They are redacted.
- Router key secrets are stored hashed. The raw secret is returned once, at creation.
- OAuth client IDs, endpoints and header requirements in this plan come from memory. Each OAuth task begins with a verification step. Confirm against the vendor CLI source before relying on them.

## Review Focus

1. **Client disconnects mid-stream.** Usage must still be recorded, so tee the stream and record in `ctx.waitUntil`. Covered in Task 6.
2. **Upstream gives no usage, or the model has no known price.** Estimate tokens from content. A key with a USD cap is rejected for an unpriced model rather than silently uncapped. Covered in Task 7.
3. **Concurrent requests at the budget edge.** Reservation must be atomic in the Hub, so overshoot is bounded by in-flight estimates. Covered in Task 7.
4. **Tool calls, multi-block content, system prompts.** `tool_use` and `tool_calls` must round-trip between formats. Covered in Tasks 3 and 4.
5. **Refresh-token rotation races.** Rotating refresh tokens (any provider that rotates) can be lost by a racing write, which logs the account out. Refresh must be single-flight, compare-and-swap, and persist before use. Covered in Tasks 8 and 9.

### Task 9: OAuth refresh hardening (re-scoped)

**Plan change (user decision, 2026-11-23).** The original Task 9 was Claude and Codex OAuth. Step 1 verification found that:
- Claude subscription tokens are only accepted from third parties that impersonate Claude Code (spoofed User-Agent, a fake "You are Claude Code" system prompt), and Anthropic's docs forbid routing requests through Free, Pro or Max logins. `claude-oauth` was **dropped**.
- Codex's briefed route uses the Codex CLI's own client ID, which OpenAI does not offer to third parties. OpenAI's official "Sign in with ChatGPT" needs its own client registration and does not cover remotely hosted apps. `codex-oauth` is **deferred**: it stays in `AccountKind` and `PROVIDERS` as an unimplemented placeholder.
- No `src/oauth/claude.ts`, `src/oauth/codex.ts` or `src/translate/responses.ts` was built.

Task 9 instead carried the hardening that Task 8's review asked for.

**Files:**
- Modify: `src/hub.ts`, `src/proxy.ts`, `src/types.ts`, `src/providers.ts`
- Test: `test/oauth-copilot.test.ts`

**Produces:**
- Compare-and-swap on the refresh persist in `Hub.getFreshToken`: only write if the stored `refreshToken` is unchanged.
- A failed refresh sets an account cooldown (60 s for network and 5xx errors, 15 minutes for 4xx rejections).
- `Hub.getAuthHeaders(accountId): Promise<Record<string,string>>`, so raw long-lived tokens no longer cross the RPC boundary on the request path.

Commit: `feat: harden oauth refresh; drop claude-oauth`
